1. Does the Project Use MVC?

Evaluating Model-View-Controller in modern declarative Jetpack Compose
ANALYSIS COMPLETE
Concept Classic MVC (2010s / Web) Modern MVVM / MVI in Compose (Active) Verdict
Model Data classes, raw SQLite queries, active records. Room Entities (ProductEntity, SaleEntity), DAOs, DataStore Preferences, and single-source-of-truth Repositories. IDENTICAL ROLE
View Imperative UI (XML layouts, DOM elements) mutated manually via controller references (view.setText()). Declarative Composables: UI is a pure function of state: UI = f(State). Composables observe immutable state and cannot be mutated imperatively. COMPOSABLE UI
Controller Intermediary object that receives user gestures and directly instructs the View what to display. ViewModel + Unidirectional Data Flow (UDF): The ViewModel acts as the Controller. It receives user Intents/Events (e.g. AddToCart), applies business rules, and emits a new immutable UiState. MODERN CONTROLLER
💡 Why We Use MVVM/MVI Instead of Classic MVC
In Jetpack Compose, traditional MVC is technically obsolete because Views cannot be imperatively updated. Instead, Android's official Clean Architecture uses MVVM / MVI with Unidirectional Data Flow (UDF). The ViewModel fulfills the Controller role perfectly by handling all user actions, updating repositories, and managing state.
