⚖️ 1. Why Dynamic Switching Wins Over a Forced Choice

When people start a business, their needs evolve. A solo shop owner might operate independently today, but partner with a supplier tomorrow, or manage both a private retail stash and partner-distributed items.

Criteria Option A: Force Choice at Signup Option B: Dynamic Mode Switching (Recommended) Verdict
User Flexibility Traps the user. If they want both, they must register 2 separate accounts and constantly log out and in. Maximum Flexibility: 1-tap switcher toggles between 👤 Personal and 🤝 Partner without re-authenticating. Winner
Business Growth Fails when an individual seller grows and signs a wholesale or co-owner agreement. Scales Naturally: Solo merchants link a partner anytime via Unique Code (MID-1001) or QR scan. Future Proof
Onboarding Friction Forces daunting configuration questions before the user has even tried the POS. Zero Setup Delay: Default to Individual Mode. User can ring up sales 5 seconds after signup. High Conversion
Data Privacy Separation is achieved, but at the cost of intense user frustration. Architected Isolation: Room DB queries strictly filter by workspace_id. Personal margins never leak. Safe
💡 Industry Standard: Notice how Shopify (Switch Stores), Slack (Switch Workspaces), and Notion (Personal vs. Team) never force users to pick one forever. They allow instant switching from the drawer with distinct store branding.

🛡️ 3. How to Make Separation Foolproof (No Accidental Edits)
Safeguard Layer Implementation in Nawano Jetpack Compose User Protection
1. Pinned Top Bar Pill The top header permanently shows a chip: [ 👤 Personal ] or [ 🤝 Partner: Nawano HQ ]. User is always 100% conscious of which store they are managing.
2. Contextual Accent Colors Personal mode uses neutral slate accents. Partner mode triggers Nawano Purple (#7871F8) borders and avatar badges. Visual muscle memory prevents ringing up personal inventory on a partner account.
3. Action Boundary Guard If a user attempts to fulfill a partner order using private stock, a confirmation modal confirms the inventory transfer. Guarantees stock counts remain strictly balanced.
🔒 4. Multi-Tenant Data Isolation (Room Database & Kotlin)

Both workspaces reside in the local SQLite database, but queries are physically scoped so personal items cannot be retrieved in partner mode:

// 1. DataStore Session manages active workspace val activeWorkspaceId: Flow<String> = sessionStore.activeWorkspaceId // "PERSONAL" vs "PARTNER_MID1001" // 2. Room DAO physically filters by workspace @Query("SELECT * FROM products WHERE workspace_id = :workspaceId ORDER BY name ASC") fun observeProducts(workspaceId: String): Flow<List<ProductEntity>> // 3. Privacy Guarantee: Margins & Personal Cash Never Sent to Partner API fun getSyncablePartnerOrders() = dao.getOrders().filter { it.workspaceId != "PERSONAL" }
